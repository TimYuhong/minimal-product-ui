# 本轮教训与长期验收

以下是设计和执行方式的纠正，不是给每个页面新增说明文字的理由。

## 已发生的问题 → 可执行规则

| 问题 | 下次怎么做 | 验收证据 |
|---|---|---|
| 未先对齐，就给页面自选品牌、配色和结构 | 新建/大改前简短说明方向；本技能默认白/深已获选择，只有实质未决问题才提问 | 改动符合用户明确方向，没有临时强加模板 |
| 把“使用官方组件”当成“官方默认页面” | 分别核对组件源码、主题变量与业务布局来源 | 来源可追溯，描述不混淆，定制如实说明 |
| 自写类似 shadcn 的封装，却没有真正复用成熟组件 | 先查项目依赖，再使用已有组件或核验官方源码 | 无重复原语、无伪称官方、许可保留 |
| 只写库名和链接，却没有取得可核验的组件实现 | 下载锁定源码，核对具体类型、样式、依赖后再实现；离线缺失就如实停止该依赖部分 | origin、commit、具体文件与校验结果可追溯 |
| 把维护者电脑路径写入公开 README | 公开说明使用相对路径/标准变量，发布前检查个人绝对路径 | 仓库检查不包含维护者机器的目录或私人运行记录 |
| 首页堆隐私/安全说明、格式教程、空状态步骤与大统计卡 | 删除非必要常驻文案；风险留在操作前，限制靠近字段，反馈按状态出现 | 用户能直接找到输入和主操作，空状态通常一句话 |
| 技能检索给出花哨/不相符方案后仍可能照套 | 将搜索结果视为候选资料，用户与项目要求优先 | 没有因模板加入渐变、装饰或额外主题 |
| 为“更多选择”增加用户没有要求的模式 | 默认白/深，其他风格需要明确需求；删除时连同初始化和旧偏好处理 | 无死入口/残留 CSS；旧值回退合法主题 |
| 只换背景，没有检查深色控件、弹窗和文字过渡 | 检查所有交互状态与实际颜色；避免层层继承文字颜色过渡 | 深色按钮、选中项、警告、焦点均可读 |
| 只看 DOM/无错误输出，未真正看截图 | 查看渲染图片，并核对信息密度、溢出与层级 | 记录实际查看过的视口与主题，不把图片元数据当视觉验收 |
| 点击后立刻读 React/Radix 状态，误判测试失败 | 等待状态、焦点或关闭动画完成，使用可重试断言 | 证明最终行为；不以随意加长 sleep 替代条件等待 |
| 状态标签和操作悬停底色相接，形成重合或厚重小框 | 按信息/操作职责安排层级与间距；必要时把状态变成轻量色标文字，不强制所有页面采用同一布局 | 白/深、窄屏、长文本、悬停和焦点状态下边界分离，触摸目标仍够大 |
| 为了减少模板感反复加背景，用户调淡时又改变数量和轨迹 | 先尊重装饰意图，分开控制强度、数量、大小、速度和范围；只修改当前要求的维度 | 无擅自新增模式；动画可关闭、后台暂停、减少动态效果时降级，不遮挡操作 |
| 把 UI 模拟成功扩大为真实业务成功 | 标注模拟、真实接口、真实副作用各自范围 | 未授权时不触发真实账号修改或部署 |

## 完成标准

根据改动风险选择最小充分证明，不要求每个文字修改都重做所有用例：

- 主流程仍满足原输入、输出、批量、导出与取消契约。
- 白/深主题的加载、空、成功、错误、禁用和确认弹窗均可理解。
- 相关测试与构建通过；浏览器无新增脚本错误或 CSP 违规。
- 窄屏约 375px、桌面及必要的横屏布局可用；长邮箱/文件名/错误不会撑破布局。
  数据表的局部滚动需有明确边界，不能变成整个页面无意溢出。
- 控件有标签与焦点；键盘 Tabs/菜单/弹窗可用，取消和关闭返回合理焦点。
  主题偏好刷新保留、存储不可用有退路、减少动态效果设置生效。
- 截图只含虚构/脱敏数据。真实凭证、访问口令和密钥不进入代码、示例或本技能。
- 交付明确哪些已测、哪些未测；任务完成后只清理已确认无用的临时产物。

## 维护时的情境检查

修改本技能后，用下面的请求检查决策是否仍然正确。结构校验不能替代这些行为判断；
没有实际运行独立代理或浏览器时，不宣称完成相应验证。

1. **“做个小工具，单行粘贴、提交、导出，不要长说明。”**
   应从简单任务布局与白/深开始，不加 Hero、卖点、虚构品牌或多输入替换粘贴契约。
2. **“后台有数千行数据，需要筛选、详情和批量操作。”**
   应保留高效导航与数据操作，用项目现有或选定的 React 组件实现；
   不为了极简删功能，也不为仿外观安装第二套完整 UI。
3. **“现有 React 项目，只修手机上的弹窗溢出。”**
   应做局部修复并核对两种主题与焦点，不更换组件库、不重做主页。
4. **“按这张参考图，用我的绿色品牌。”**
   应尊重明确参考；白/深的可读性与克制原则仍适用，不强制黑白主按钮。
5. **“删除一个主题，保持其余行为。”**
   应覆盖入口、类型、CSS、持久化和启动初始化，兼容旧偏好，不清掉业务数据。
6. **“模拟结果很好，现在帮我测试真实账号。”**
   应确认真实副作用的授权与范围；截图和 mock 不构成真实验证，不复用技能中的凭证。
7. **“这个 React 项目可以使用 HeroUI，但现有 shadcn 组件运行正常。”**
   应先比较现有覆盖与实际收益，不直接安装第二套 UI；若选择 HeroUI，
   核对主版本与主题方式，不复制旧版 Provider 教程，也不自动注册其 MCP。
8. **“也可以用 React Bits，但页面仍要轻量、干净。”**
   应先完成静态可用的白/深基线，只选能改善实际体验的局部组件；
   不默认添加 WebGL 背景，不整体安装演示站依赖，不把附加许可误称为普通 MIT。

维护时优先修正有真实证据的判断规则；新增规则应能解决具体失败，
不要把技能扩成通用前端教材、项目操作日志或无限增长的禁止清单。
