# Liquid Glass React：局部液态玻璃

用户明确需要液态玻璃时读取。保留项目既定主题，将材质应用于指定表面，
例如弹窗、工具栏或浮层；加入来源不构成自动美化所有卡片或替换业务组件的要求。

## 实现与参数

默认导出为 `LiquidGlass`。当前 peer 依赖为 `react >=18`、`react-dom >=18`，
没有额外的生产运行时依赖；开发依赖和示例 Next.js 依赖不属于组件的安装清单。

实现使用 SVG 位移/色彩分离滤镜、CSS backdrop blur、边缘高光及鼠标位置反馈。
`shader` 模式通过 Canvas 2D 逐像素生成位移图，不是 WebGL；尺寸变化时会重新生成。

| 参数 | 当前公开默认值 | 使用时核对 |
|---|---|---|
| `mode` | `standard` | 可选 `standard`、`polar`、`prominent`、`shader`；按实际浏览器检查 |
| `displacementScale` | `70` | 折射量；在真实背景上观察边缘，不让内容难读 |
| `blurAmount` | `0.0625` | 是计算参数而非直接的 px；上游用它参与 blur 值计算 |
| `saturation` | `140` | 背景饱和度百分比，不作为业务状态色 |
| `aberrationIntensity` | `2` | 色散强度；按需求调节，避免明显彩边干扰文字 |
| `elasticity` | `0.15` | 鼠标弹性；减少动态效果时置零并处理过渡/监听 |
| `cornerRadius` | `999` | 胶囊默认值；随目标表面形状调整 |
| `padding` | `24px 32px` | 公开实现默认值；结合内部原有组件间距，避免双重内边距 |
| `overLight` | `false` | 浅色背景会改变阴影和叠加层，需实际验收，不能仅按主题名称判断 |

`mouseContainer` 可指定跟踪容器；`globalMousePos` 与 `mouseOffset` 同时提供时会跳过内部鼠标监听。
不凭参数名称保证某个设置已经实现“原生系统同款”效果。

## 分别控制材质、交互、可读性与计算成本

先确认采用玻璃的表面、背景和交互职责，再选择实现。可在同一组件中组合下列层，
分别调整与验收，避免为了加强材质同时改变控件位置、焦点、阅读或计算方式。

| 维度 | 负责什么 | 适配与验收依据 |
|---|---|---|
| 材质表现 | 背景折射、边缘厚度、高光、色散及必要的光学弹性 | 在真实背景上观察双轴扭曲；独立调整位移、遮色与高光，控制重复轮廓和彩边 |
| 交互语义 | 标签、键盘选择、焦点、关闭、禁用、选中与确认 | 继续由已有成熟原语承担；装饰层不截获指针，确认和输入输出契约保持一致 |
| 可读性 | 前景内容对比、文字清晰度及背景干扰 | 文字和按钮位于清晰内容层；可将清晰折射边缘与柔化阅读内层分开，按真实背景与主题复验 |
| 计算成本 | 位移图生成、滤镜合成、动画与资源生命周期 | 区分一次生成与持续渲染；限制面积和触发频率，隐藏/离屏/减少动态效果时停止非必要响应 |

- **只有磨砂感**：先检查折射是否实际生效、背景是否有可观察信息、遮色是否过厚。
  纯色背景上的变化可能很弱；不要为证明折射向业务页面堆入无关图案。
- **文字随材质晃动**：对表单、确认和选择浮层，优先让弹性只影响背景光学层与高光，
  保持内容和点击目标稳定；若设计确需整个控件变形，另验点击、焦点环与触屏边界。
- **小菜单与大弹窗共用材质**：共享来源与主题，按尺寸、背景及用途调整折射量、圆角、
  模糊和色散；不要把一组演示参数推广到所有表面，也不因加入玻璃自动添加持续流光。

## 位移图的通道与尺寸检查

源码来源通过核验后，继续检查素材与滤镜的配合：`feDisplacementMap` 读取的
`xChannelSelector` / `yChannelSelector` 必须对应图片真实编码，并核对中性值、
位移正负方向和当前模式。可以解码图片抽样通道范围；仅有滤镜 DOM、CSS 支持或高光不能证明折射正确。

在本参考锁定的 v1.1.1 中，`prominentDisplacementMap` 的 R/G 通道有变化而 B 为常数 0，
`GlassFilter` 的两个选择器为 R/B。这一组合可能使纵向成为固定偏移，需在实际浏览器检查；
`shader-utils.ts` 生成器明确把纵向值同时写入 G/B，并由 `index.tsx` 为 shader 模式选择相应的位移方向。
这项观察限定于上述素材与版本；其他静态位移图通过编码、方向和渲染验证后仍可使用。

固定方形位移图拉伸到长条或大弹窗时，要检查边缘厚度、角部和纵横比例。
几何或编码确有问题时，可在核验上游生成器后按表面尺寸生成位移图；保留宽高比并给生成像素数设上限，
例如小浮层可评估 512×320 的尺寸预算，但这只是成本示例，需随目标设备、尺寸和清晰度调整。
生成图应在解码成功后启用；生成失败或能力不支持时回到可读表面，不留下空白或阻塞操作。

## 接入前必须处理的边界

- **SSR**：当前实现会在渲染中访问 `navigator`，effect 中使用 `window`/Canvas。
  Next.js 的 `use client` 本身不保证跳过服务端预渲染；需要真正的客户端加载边界，
  或在保留来源的局部适配中防护浏览器 API，再验证 hydration。
- **语义与 ref**：公开 `LiquidGlass` 的 `onClick` 落在 `div`，未提供按钮的键盘、disabled 或 ARIA 行为；
  公开组件也未透传任意 DOM props/ref。不要直接作为 Radix `asChild` 的替代节点。
  将材质与既有 Button/Dialog 原语分层组合；装饰层不截获指针，焦点环、Escape、焦点返回及名称均保留。
- **下拉与滚动**：传统原生 `select` 的系统弹出层不受普通 CSS 完整控制。需要统一玻璃外观时，
  先比较目标浏览器的原生可定制能力与已有 Select/Menu 原语；表单选择与设置项单选按实际语义选型，
  保留键盘、选中反馈和触屏操作。非模态设置菜单可使用原语的非模态模式。
  模态、焦点保护与滚动策略分别确认；用户要求弹窗外页面可滚动时，检查 Overlay/RemoveScroll 的具体位置，
  保留必要的焦点和外部点击保护。不要把菜单的非模态选择推广到危险操作确认弹窗。
- **样式**：实现含 Tailwind 工具类而没有独立 CSS 文件。项目需要确保采用的类实际生成；
  已使用其他样式方案时，可核验后转换为局部样式，不为材质强制迁移全局样式系统。
  注意默认白字、20px 内容字号和阴影，接入项目 token 并记录这些定制。
- **定位**：默认计算包含 `translate(-50%, -50%)`，并覆盖传入 style 中的 transform。
  检查定位容器及多层高光的坐标；不能直接嵌入普通文档流，或覆盖 Dialog 原有居中/缩放而不验收。
- **尺寸**：上游挂载及 window resize 时测量，缺少 ResizeObserver。
  内容、字体、展开状态或父容器尺寸变化时需要对应适配，避免位移图和边框停留在旧尺寸。
  滤镜定义 SVG、装饰层与边框盒也要检查：装饰层溢出几像素就可能触发内部滚动条。
  先修尺寸约束；隐藏可见滚动条时，长内容仍须能查看、操作与关闭。
- **浏览器与 CSP**：上游 README 明示 Safari/Firefox 部分支持，位移可能不可见。
  在目标浏览器检查实际效果；缺少滤镜时保留可读的静态表面和操作，不承诺跨浏览器外观一致。
  检查 SVG `url(#...)`、内嵌/Canvas data URL 与现有 CSP 的兼容性，不为效果放开整个安全策略。

## 视觉、性能与验收

- **材质证据**：在真实浅/深背景、滚动内容和图片上检查折射、色散、边框、文字及焦点。
  可固定背景、指针与动画状态，只切换折射层作渲染对照，再实际查看差异；像素不同仍需确认变化符合预期。
  动态质感必要时用短录制观察背景穿过边缘时的扭曲和回弹，不能仅凭单张截图或演示参数判通过。
- **生成与渲染预算**：先比较已验证的静态图与局部 shader；逐像素生成成本随面积增长。
  生成可在挂载、内容布局变化或 resize 后按需触发，跳过相同尺寸、合并密集回调并释放临时 Canvas/监听。
  指针反馈优先更新光学参数，不逐帧重新生成位移图；不默认用于大面积或大量列表项。
  浏览器生成一次图后，SVG/backdrop 合成与动画仍有客户端 CPU/GPU 成本，需按设备和实例数观察。
  常规静态站点的这类效果主要由浏览器计算；服务器仍承担静态资源传输，不能泛称“完全零资源消耗”。
- 上游没有完整的减少动态效果策略；项目需处理 `prefers-reduced-motion`、触屏和后台状态。
  `elasticity=0` 只限制弹性，并不自动取消所有监听、滤镜或 CSS transition。
- **交互与边界**：检查桌面、窄屏及长内容，等待布局、焦点和入场动画到达最终状态再测量/断言。
  验证菜单选中、方向键/Escape、关闭焦点返回、外部点击及约定的滚轮/触摸滚动；检查多个实例的滤镜 ID。
- **降级证据**：分别记录目标浏览器的实际测试与降级策略，检查无滤镜、高对比和减少动态效果时仍可阅读与操作。
  CSS 特性检测、伪装 User-Agent 的降级用例不能替代真实浏览器引擎测试；Chrome 通过不代表 Safari/Firefox 等效。
  无真实运行或性能测量时准确说明未验证项。

遇到“仍然像磨砂”反馈时，依次复查通道/方向、素材几何、实际背景、模糊与遮色、动态响应，
一次调整有共同原因的一组问题，在同背景与视口复验。达到可辨认的材质、稳定的交互、清晰的内容与合理成本后停止扩展。

