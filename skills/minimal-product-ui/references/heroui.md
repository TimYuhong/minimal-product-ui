# HeroUI：可选主组件方案

官方资料：

- 仓库：[heroui-inc/heroui](https://github.com/heroui-inc/heroui)
- 当前 React 文档：[HeroUI React](https://heroui.com/docs/react/getting-started/quick-start)
- 旧版文档：[HeroUI v2](https://v2.heroui.com/)

把 HeroUI 当成有自己组件、可访问性与主题体系的 React 库，不只是外观皮肤。
它可以直接提供项目的基础组件，与 React Bits 等局部交互/动效组件的职责不同。

## 选型之前

1. 先查 package.json、锁文件和实际导入，确定项目是否已使用 HeroUI、NextUI 或其他主组件库。
   不因用户允许参考 HeroUI 就自动安装、替换现有 shadcn 组件或启动全量迁移。
2. 核对所采用的准确版本、对应文档、React/React DOM/Tailwind 的 peerDependencies、
   样式入口、组件 API、SSR/客户端边界。不要把 v2 的安装、Provider、动画依赖和主题写法
   原样带到 v3，也不以未来最新版文档解释现有锁定版本。
3. 对比维护方式：shadcn 侧重项目内源码定制，HeroUI 侧重发布包、公开组件 API 与主题能力。
   两者源码都可查看，但不宣称包依赖与复制到项目的源码有相同的升级/定制成本。
4. 用对应版本支持的按组件导入、样式与主题扩展机制。确需新增依赖时说明原因，
   锁定版本并验证实际构建产物，不笼统承诺“按需导入一定更小”。

## 与极简白/深基线配合

- 沿用组件的键盘、焦点、ARIA 与弹窗行为；优先通过官方主题变量、公开样式槽或组合 API 定制。
  不靠复制整份内部源码、依赖私有选择器或大面积 !important 覆盖来维持外观。
- 去掉与任务无关的光晕、渐变、装饰、过大圆角和营销布局，而不是删除必要的交互反馈。
  HeroUI 的默认示例不是强制页面模板。
- 仅接入一套语义主题与切换入口，覆盖白/深、悬停、焦点、禁用、错误与弹窗。
  复用项目已有主题提供方式，避免样式层、reset 或颜色变量与 Tailwind/shadcn 相互覆盖。
- 如果项目已经稳定使用其他组件库，只为一个按钮引入 HeroUI 通常不合算。
  若用户明确要求迁移，先明确组件覆盖、样式冲突、可访问性、升级边界与回退范围。
- 浏览器验收表单、选择器、Tabs、弹窗、手机布局和主题持久化；“React Aria 提供基础支持”
  不等于业务组合天然无障碍或不必测试。

## 本次核验与易变信息

2026-10-23 查阅时，仓库默认分支为 `v3`，React 包清单版本为 `3.2.6`；
该分支 README 描述为 React Aria、Tailwind CSS v4、React 19 的组合，
并说明 v3 不要求 Provider 包裹。实际 peerDependencies 和使用要求应在每次选型时重查，
这段核验记录不是永久安装指令，也不要求为引用它升级现有项目。

仓库根 LICENSE 与 React/样式包的 license 元数据在本次查看时存在不同表述。
采用或复制时核对具体版本与具体文件的许可；未澄清前不要笼统写“整个项目都是 MIT”
或“所有包都采用仓库根许可”。保留适用声明。

本技能不依赖 HeroUI MCP、CLI、Figma 或附加 skills。只查文档不授权执行文档中的
安装命令、修改代理配置或注册 MCP；实际项目需要时按用户任务范围处理。
