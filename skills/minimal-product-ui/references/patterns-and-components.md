# 模式与组件选择

先看现有依赖与真实业务，再选最少的必要组件；下面是选择依据，不是安装清单。

<a id="component-decision"></a>

## 从问题主动发现组件

新建页面、明显视觉重构或已发现体验缺口时执行以下决策；局部任务只覆盖相关职责。
用户不必先给出组件名称，组件库也不决定页面应该长什么样。

1. **定义要改善的结果。** 将观察转成具体问题，例如“结果与输入没有层级，用户看不到处理状态”，
   而不是“页面太简单，增加组件”。说明期望改善的区域、状态与可观察结果。
2. **先查项目。** 检索组件目录、实际导入、依赖和相似页面，记录能直接复用、组合或小幅定制的实现。
   CSS 布局、已有组件和保持现状均是候选，不重造已有成熟原语。
3. **先初筛，再核验入选候选。** 用下表、项目依赖和可信目录/资料按职责缩小范围，
   有层次、呈现或反馈缺口时主动考虑 Magic UI、Aceternity UI、React Bits 中适合的能力，不逐库巡检。
   例如 empty、tabs、progress 只是搜索线索，不是已确认的 API。
   对有采用可能、值得进一步比较的具体候选，按 [源码规则](source-policy.md) 获取/核验对应来源并读取实现；
   不为显然不相关的库下载完整源码或制造拒绝记录。初筛未读源码时注明依据，不声称已验证兼容性。
4. **比较收益与代价。** 对照既有实现/低成本方案，比较视觉或任务收益、设计语言适配、依赖增量、
   包版本与 API、许可、键盘/触屏/减少动态效果、SSR、加载与运行成本以及长期维护。
   先解决许可和兼容性门槛，不能用视觉收益抵消这些缺口。基础组件已足够时无需强行跨库比选。
5. **作出取舍。** 采用、复用定制、暂缓或拒绝；保留已有成功设计是有效结论。
   采用前读具体实现、类型、样式和依赖，记录来源/版本；不能仅凭演示截图或 README 宣称复用。
   只为实际比较过的候选简述关键理由，不为凑候选数或制造差异引入功能、动画或依赖。

在任务记录或交付中保留简短决策证据即可，无需新建报告文件：

| 界面问题与位置/状态 | 项目候选、具体上游候选或无依赖方案 | 收益与主要代价 | 决定及验证方式 |
|---|---|---|---|
| 实际观察；没有截图时标为假设 | 路径/组件名/来源 ID；未核验要标明 | 是否更清楚、更易用、符合设计语言；新增成本 | 复用/采用/暂缓/拒绝；用何种截图或交互证明 |

## 按职责组合，不按演示站拼页

| 层级 | 负责什么 | 组合边界 |
|---|---|---|
| 基础 UI 原语 | 标签、输入、菜单、Dialog、键盘与焦点语义 | 由项目现有主库、shadcn/Radix 或 HeroUI 承担，不叠加重复基础体系 |
| 视觉增强组件 | 内容强调、展示方式、局部材质与视觉层次 | 可使用 Magic UI、Aceternity UI、React Bits；接入 token，不取代语义控件 |
| 动画与交互反馈 | 状态转变、空间连续性、图标反馈 | 先 CSS/既有运行时，再按需 Motion/Morphicons；不重复控制同一元素 |
| 业务组合组件 | 输入、校验、结果、筛选等任务流程 | 用前述组件组合，沿用真实数据与权限，不凭视觉新增业务 |
| 页面整体布局 | 阅读顺序、导航、密度、响应式分区 | 按产品任务设计；不直接采用组件演示页、营销模板或固定卡片网格 |

例如已有 Dialog 可继续承担焦点与关闭语义，内部复用结果列表，并给真实成功状态加局部反馈。
这不构成引入另一套弹窗库或照搬演示页的理由。

## 按场景组织界面

- **短表单/工具站**：让标题、输入、主操作、空/处理中/结果形成清楚层级；
  内容少时检查宽度、分组和结果表达，不满足于把输入框放在大空白中央，也无需通用管理后台外壳。
- **批量导入**：保留用户定义的粘贴/文件契约，解析结果靠近输入；
  处理后用真实行状态、筛选与导出，不默认添加大数字统计卡和常驻教程。
- **管理后台**：导航只承载真实模块；页面工具栏聚合搜索、筛选与操作，
  数据区优先列表/表格、行详情和就近状态。复杂度需要时再分栏或加侧栏。
- **长任务**：显示可观察的阶段、进度与失败原因，区分取消等待与撤销已发生的副作用；
  不用动画或假进度代替真实状态。
- **帮助和风险**：常驻一行必要提示或可展开帮助；后果重要的操作在确认时说明，
  不把工程说明、平台声明和隐私卖点铺满首页。

## React 生态按需选用

| 需求 | 来源 ID 与使用条件 | 不需要时 |
|---|---|---|
| 按钮、表单、Tabs、Dialog、菜单 | `shadcn-ui`：需要源码可控的基础组件；`radix-primitives`：需要无障碍交互原语；`heroui`：已有 HeroUI 或选作完整主方案 | 先复用项目；不叠加两套主组件库，不重造焦点/键盘原语 |
| 样式与语义主题 | `tailwindcss`：项目已用或明确选择 Tailwind，核对当前大版本的主题与插件 API | 不为重置颜色迁移构建工具或 Tailwind 大版本 |
| 常规图标 | `lucide`：按钮、状态、导航需要一致图标时，使用 React 绑定或已核验的图标数据 | 不再装一套近似图标库，不用 emoji 代替结构图标 |
| 图标状态变形 | `morphicons`：复制/成功、展开/关闭、播放/暂停等变化能帮助理解操作时 | 不把每个静态图标都变成动画，不替代按钮和状态逻辑 |
| 简单状态 | React 本地状态与现有上下文 | 不为少量字段安装状态库 |
| 跨模块共享客户端状态 | `zustand`：多个视图确实共享状态且本地状态/现有 Context 不再合适时 | 不为少量字段引入全局 store；不与服务器数据缓存重复管理同一状态 |
| 服务器状态缓存/重取/去重 | `tanstack-query`：需要查询生命周期、失效、缓存或乐观更新时 | 简单请求保留合理的现有实现，敏感数据不默认持久化 |
| 布局、离场和手势动画 | `motion`：CSS 难以表达的布局/手势/编排；先复用项目已有 Motion/Framer Motion | 不为一个淡入安装动画运行时，不同时安装两套等价入口 |
| React 局部视觉组件 | `react-bits`：发现内容展示、层次或局部交互可改善时主动评估，先查成本和许可 | 不整体搬入演示站，不默认 WebGL/粒子背景 |
| 液态玻璃材质 | `liquid-glass-react`：用户明确选择折射、边缘高光和弹性效果时，先阅读专项参考 | 不替代 Dialog/按钮语义，不自动叠加其他玻璃实现或改整页主题 |
| 精选视觉增强 | `magic-ui`：内容展示、视觉焦点或反馈存在明确缺口时，在设计阶段即可比较具体候选 | 不因为库提供动画卡片就重做工具页面 |
| 特定视觉构图/组件 | `aceternity-ui`：公开组件能改善已识别的问题并符合产品语言时主动评估 | 不套营销模板，不下载付费 blocks/templates，不假定全部 MIT |
| 用户需要可调分栏 | `react-resizable-panels`：需要拖动分隔条、尺寸约束或布局恢复时 | 静态两列用 CSS Grid 即可 |
| 用户需要拖拽排序/移动 | `dnd-kit`：真实排序/移动需求，保留键盘与非拖拽替代操作 | 不因“交互感”添加拖拽 |
| 真实数据图表 | `recharts`：数据比较或趋势确实需要图形表达时，配合空/错状态和必要文字摘要 | 单个数字不必画图，不虚构数据 |

新增依赖前交代必要性与复用结果。使用 shadcn 官方源时核实注册表、许可、
导入路径及兼容性；可记录来源与改动，但不宣称业务布局也是官方模板。

## 版本与来源陷阱

- 矩阵的 ID 对应 `upstreams.json`，操作前按工作流核验。快照不是项目默认安装版本。
- `react-resizable-panels` 是准确包名。缓存包含 `Group`、`Panel`、`Separator` 等当前实现，
  旧版 `PanelGroup`/`PanelResizeHandle` 的示例不能直接混用。
- dnd-kit 当前快照包含新 `@dnd-kit/react` 系列；使用旧 `@dnd-kit/core`/`sortable` 的项目，
  要另取匹配版本，不能只因同属 dnd-kit 就替换 API。
- Motion 的 `motion/react` 与已有 `framer-motion`、Tailwind v3/v4、TanStack Query 大版本，
  都先核对包与导出。Lucide 的 React 组件与 IconNode 数据也不是同一种输入。
- Lucide 含不同来源的图标许可，应读根 LICENSE 与具体图标声明；不要因 API 返回 NOASSERTION 就猜许可。

## Morphicons：可选图标反馈

- 官方来源为 `guillermolg00/morphicons`，React 入口 `morphicons/react`，许可 MIT。
  阅读 `src/react/index.tsx`、`src/core/types.ts` 与 `src/dom/` 的实际行为后使用。
- 接收 IconNode 或 SVG 路径字符串，不能直接把 `lucide-react` 的 React 组件传入。
  可以使用匹配的 Lucide 数据导出或按许可提取所需路径，避免再装整套近似图标库。
- 用在能表达真实操作状态的少数控件上；按钮仍采用既有成熟组件，保留文本/aria-label、焦点和点击目标。
  禁止因“点了有动画”就让静态列表所有图标持续变形。
- 当前源码默认 `reducedMotion="never"`，项目接入应显式选择 `reducedMotion="user"`。
  上游宣称的体积不代替目标构建实测；尤其核对填充图标额外懒加载与同页大量实例的成本。
- 该库内部已有弹簧动画，不为同一图标额外安装 Motion。它也不承担卡片、布局或表单组件职责。

## Aceternity：官方公开注册表

- 官方来源为 `https://ui.aceternity.com/registry.json` 及其逐项注册表 URL。
  本技能缓存公开 `registry:ui` 条目和提取的源码，原 JSON 与源码由 SHA-256 锁对应。
- 不把个人演示仓库冒称官方源码。公开注册表可下载不等于所有条目均采用 MIT；
  当前保存官方 licence/terms 页面作为许可证据，使用前逐项确认免费/Pro 与第三方声明。
- 缓存供本地核验，不重分发组件源码包。付费 blocks、templates 和未取得授权的代码不属于下载范围。
- 普通任务不刷新哈希以绕过失败。需要更新快照时，维护者显式运行
  `python scripts/ui_sources.py refresh-registry --source aceternity-ui`，检查变化和许可后再发布锁定清单。

## Liquid Glass React：可选液态玻璃

官方来源为 `rdev/liquid-glass-react`，默认导出 `LiquidGlass`，MIT 许可。
实现、实际参数与边界见 [liquid-glass-react.md](liquid-glass-react.md)。
SVG 折射、背景模糊、边缘高光和弹性分别控制；与现有 React Bits 玻璃适配比较后选择一种局部方案。
采用前检查 SSR、样式工具类、居中 transform、真实背景及焦点组合，不直接套用演示站。

## HeroUI 的使用边界

用户提供的官方仓库：[heroui-inc/heroui](https://github.com/heroui-inc/heroui)。
可选为 React/Next.js 项目的主组件方案，特别是已有 HeroUI 或需要一致的表单、
选择器、弹窗、数据展示组件时。选用前阅读 [heroui.md](heroui.md)。
按业务需要组织 React 页面，不为借鉴布局再安装另一套 UI 框架。

HeroUI 与 shadcn/Radix 优先择一承担同一层组件职责。不是要求移除 HeroUI 自身的
传递依赖，也不是禁止复用项目里已有的局部组件；需要混用时先明确边界，
避免重复主题、全局 reset、焦点管理和覆盖样式。

## React Bits 的使用边界

用户提供的仓库：[DavidHDev/react-bits](https://github.com/DavidHDev/react-bits)。
它提供可选的组件与动效源码，不是必须整体安装的基础 UI 框架。
准备采用时阅读 [react-bits.md](react-bits.md)：匹配 JS/TS 与 CSS/Tailwind 版本，
核对该组件自己的依赖、许可、可访问性和性能，不把演示站点依赖全部搬进项目。

在设计阶段即可评估局部组件，最终页面仍应在关闭非必要动效时完整可用。
没有明确需求时，不采用粒子、光效背景、光标追踪、文字轮播或 WebGL 作为默认装饰。

范围限定为 React/Next.js。保留项目现有构建、路由、组件和主题约定；
推荐技术栈不构成重写授权，不引入其他框架的 UI 套件作为默认参考。


## 项目内部共享组件与卡片体系

<a id="component-reuse"></a>

本节补充项目内部组件的发现、复用和验收规则。它与上游源码核验互补：上游源码规则证明第三方来源和 API，本文证明项目内部组件是否真正被复用。视觉相似不等于代码复用。

### 先盘点本次范围内真实存在的组件

新建页面、明显重构或跨页面一致性调整时，先检查本次范围内的页面、组件目录、实际导入、样式文件和相似页面。局部修复只盘点受影响组件及其相邻依赖，不扩展成全站清查。

按职责整理实际发现的组件，至少能回答：

| 盘点对象 | 要检查的内容 | 可作出的决定 |
|---|---|---|
| 页面与布局 | 页面分区、容器、导航、工具栏、列表/表格、弹窗和滚动区域 | 保留、调整布局、复用现有布局组件或抽取共享结构 |
| 重复结构 | 相似 JSX、重复 CSS、相同信息层级、相同操作和状态 | 复用现有组件、抽取共享组件、合并变体或保留有依据的差异 |
| 卡片与信息容器 | 标题、主内容、指标、辅助信息、状态、操作区及表面样式 | 使用现有 Card、建立基础 Card、组合业务卡片或不使用卡片 |
| 小组件 | 状态徽标、复制反馈、筛选、选择工具栏、二次验证、输入控件、菜单、提示、空/错/加载反馈等实际存在项 | 统一样式、补齐状态、复用交互原语或保持现状 |
| 交互状态 | 每类组件实际支持的状态及状态切换入口 | 补齐缺失状态、修复反馈或标记不适用并说明原因 |

不要把表中示例当成固定组件清单。必须从真实源码发现本次范围内的组件；不得只处理提示词点名的两三个控件，也不得虚构项目没有的组件或功能。

### 共享 Card 基础与语义变体

当多个位置存在相同职责、相似结构或一致交互的卡片时，优先复用项目已有 Card；没有合适实现时，再建立共享基础组件和少量语义变体。不要为了满足“卡片化”而把表格、列表、工具栏、表单或纯文本区域强制包装成卡片。

共享基础应明确其结构职责，按项目实际需要组合以下区域：

- 表面容器：背景、边框、圆角、阴影、主题和整体尺寸。
- 标题区：标题、说明、图标及可选的头部操作。
- 内容区：主要信息、指标、表单或业务内容。
- 辅助信息区：时间、来源、描述、标签或次要元数据。
- 状态区：成功、警告、错误、处理中等语义状态。
- 操作区：主次操作、更多菜单及其间距和对齐。

这些区域是可组合的职责，不要求每张卡片都包含全部区域。基础 Card 负责稳定的表面和结构；统计、状态、任务、凭证/结果、参数、快捷操作等业务卡片通过明确的语义变体或组合组件表达差异。名称只是候选，以真实业务为准。

实现时遵循以下边界：

1. 相同职责、结构和交互优先复用同一个基础组件或组合组件；变体只表达确有必要的差异。
2. 优先采用项目已有的 props、slot、children、子组件或 variant 机制；沿用现有设计 token，不建立第二套颜色、圆角、阴影和间距。
3. 避免每个页面复制近似 JSX/CSS；也避免把所有业务差异塞进一个包含大量互斥布尔属性的巨型 Card。
4. 只有一个实例、结构确实不同或抽象会增加理解成本时，可以保留局部实现，并说明不抽取的理由。
5. 卡片数量、网格列数、等高和装饰均由内容与任务决定，不作为完成度指标。

### 小组件按职责统一，不按示例局部修补

对本次范围内实际存在、且确有优化必要的小组件逐项检查。识别线索包括状态徽标、凭证/结果字段、复制按钮与反馈、2FA/验证提示、筛选器、选择工具栏、标签、输入控件、菜单、提示、分页、空状态、错误状态和加载反馈等。

每个相关组件检查：

- 尺寸、内外边距、最小点击区域和相邻控件间距；
- 图标尺寸、描边/填充风格、图文基线、文案长度和截断/换行；
- 颜色角色、文字对比度、背景、边框、圆角、阴影和主题表现；
- default、hover、focus、pressed、selected、disabled、loading、success、error 等适用状态；
- 点击区域、键盘可达性、焦点可见、ARIA/标签语义和触屏可用性；
- 操作后的反馈位置、持续时间、错误解释、取消与恢复路径；
- 与同职责组件、卡片、工具栏和页面整体的比例与对齐。

同职责组件保持一致；不同职责组件保留必要差异。不要为了统一而删除有用信息、弱化操作语义或改变业务行为。

### 组件状态矩阵

在新建/明显重构或组件状态是本次问题核心时，按职责列出适用状态。无需机械穷举所有组合；不适用项标记为 N/A 并说明原因。

| 组件/职责 | 适用状态 | 触发方式 | 预期视觉与行为 | 实际结果/证据 |
|---|---|---|---|---|
| 实际组件名与源码路径 | default / focus / loading 等 | 点击、键盘、请求或数据条件 | 用户应看到什么、能做什么、如何恢复 | 路由/视口/状态、操作结果或截图 |

### 代码复用的验收证据

完成后必须从源码确认，而不是只看截图。交付记录至少包括：

- 共享组件定义文件、导出名称及其承担的稳定职责；
- 两个或更多适用调用点的文件路径和导入/使用关系；只有一个合理实例时说明不抽取的理由；
- 变体/组合如何表达差异，以及 token、样式或主题如何保持一致；
- 仍存在的相似 JSX/CSS、未迁移调用点及保留原因；
- 对小组件的实际盘点范围、已优化项、保持不变项和未检查项。

截图用于证明渲染结果，源码路径和调用点用于证明复用，实际交互用于证明行为；三类证据不能互相替代。没有源码或浏览器条件时，明确标记未验证，不得把计划写成已完成。
