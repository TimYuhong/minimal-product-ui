# 视觉方向与可选基线

先明确页面服务谁、最重要的任务/内容、使用频率与信息密度，再选择视觉表达。
既有项目沿用品牌、token、字体和组件尺度；新项目根据产品用途提出有理由的方向。
简洁、现代是质量目标，不等于所有页面使用同一种配色、圆角或布局。
按项目的 Tailwind 版本、CSS 变量和主题机制接入，不在设计系统旁再造平行变量。

## 层次、构图与内容密度

- 让视觉权重对应任务优先级：用位置、分组、字重/字号、对比或适度色彩突出当前核心任务，
  不要求所有页面有大标题或强色按钮，也不让装饰抢过主要内容。
- 根据内容决定宽度与分区：工具关注输入到结果，内容页关注阅读节奏，后台关注数据与操作效率。
  空白应有分组、阅读或等待内容的用途；过于单薄时先改善真实内容、状态和结果展示，而非填装饰。
- 卡片、分割线、分栏、渐变、材质和背景都是可选手段，无强制默认。
  比较它是否帮助分组、聚焦或表达产品特征，且不掩盖内容；不用组件演示页替代信息架构。
- 视觉与交互的检查和修复证据统一按 [视觉审查](lessons-and-acceptance.md#visual-review) 记录。

### 布局取舍要回答的问题

新建/明显重构的设计简报先确定信息结构，再解释视觉语言；关键屏用文字线框、截图标注或低保真草图即可。
对确有合理备选的结构作比较，不要求固定数量的方案，也不为局部修复重做全页设计。

| 结构决定 | 依据与需要说明的代价 |
|---|---|
| 单列、分栏、导航与分组 | 内容是否需要同时比较，主要阅读/操作顺序是什么，窄屏如何重排；不是按演示页或对称偏好决定 |
| 常驻与按需入口、主次操作位置 | 任务频率、可发现性、触控距离、误触及恢复成本；隐藏常用操作必须有任务依据 |
| 密度与首屏、滚动归属 | 哪些内容必须先看到，长名称/长列表如何保持可读，哪个容器滚动或吸附、到末尾发生什么 |
| 字体、颜色、表面与动效 | 怎样支持上述任务层次、状态和既有产品识别；不能只用配色名或“高级感”解释方案 |

选择方案时说明采用理由和最关键的代价，并把可能失效的条件加入本次场景清单。
不预设所有卡片等高、列表更密一定更好或滚动越少越好；按任务及数据验证。

## 语义颜色与可选纯白/深色样例

沿用或建立有角色的颜色：背景、表面、内容、主操作、焦点及状态。品牌色、暖/冷中性色等
可以合理采用，不需要先改成黑白再微调。用户明确要求极简纯白，或该方向确实适合产品时，
可采用下表；数值是可选起点，不覆盖现有 token，也不是所有项目必须通过的颜色断言。

| 角色 | 纯白 | 深色 |
|---|---|---|
| background | #FFFFFF | #09090B |
| surface | #FFFFFF | #111113 |
| foreground | #18181B | #F4F4F5 |
| muted | #F4F4F5 | #232326 |
| muted-foreground | #66666E | #A1A1AA |
| border | #E4E4E7 | #303036 |
| input-border | #8A8A93 | #71717A |
| primary | #18181B | #F4F4F5 |
| primary-foreground | #FAFAFA | #18181B |
| focus-ring | #52525B | #D4D4D8 |
| destructive | #B91C1C | #FCA5A5 |
| success | #166534 | #86EFAC |
| warning | #92400E | #FCD34D |

普通正文及按钮文字目标至少 4.5:1。装饰性分隔线不等同于控件边界；
若输入框依靠边界才能辨识，应提供足够的非文本对比度（通常 3:1）。
语义状态必须同时有图标或文字，不只靠红绿颜色。新的状态底色需另验对比度。
装饰色不能兼任相冲突的状态语义；任何配色都要检查实际文字、焦点与控件边界对比度。

## 排版与空间

- 优先系统字体或项目现有字体；只有产品表达确有收益且加载、许可和回退可控时才引入新字体。
- 正文通常 14–16px，字段与操作名称清楚可读；移动端输入通常 16px。
  标题尺度由信息层级与产品表达决定；20–24px 可作为紧凑工具的例子，不是全局上限。
- 触屏操作目标宜至少 44×44px；密度提升不能以缩小点击区域、降低标签可读性或隐藏常用操作为代价。
  保留键盘导航、焦点可见、弹窗关闭和焦点返回，复验触屏与键盘的实际路径。
- 沿用项目间距尺度；没有既有尺度时，可从 4/8/12/16/24/32px 的有限序列选择。
  页面宽度取决于任务：短表单不要撑满屏，表格也不要被窄卡片挤压。
- 圆角、边框、阴影按组件职责和设计语言统一；纯白极简方向可从小圆角、细边框、少阴影起步。
  不是每一层都要套卡片；选择组件库现有尺度时保持内部一致，不硬覆盖每个组件。
- 简单工具可用单列，必要时输入/结果双列；管理后台按功能采用导航、工具栏与数据区。
  手机自然堆叠，长文本换行，动作不溢出；大数据表可有受控的局部横向滚动。

## 主题与动效

- 浅/深是外观模式，不是固定风格。新建完整界面通常支持浅色与深色的等价体验，
  浅色可为纯白或符合产品的其他配色；用户明确单主题时遵从。沿用项目系统主题策略与入口，
  不为局部任务增加切换器或另一种主题，也不为配色变化增设多个可选风格。
- 若持久化，只存外观偏好。存储被禁用也应可切换；无效或已移除值回到合法默认。
  用项目既有静态资源/初始化方式避免闪烁，不塞入 CSP 不允许的内联脚本。
- 按钮、标签页与输入反馈可用约 120–200ms 的颜色/透明度过渡，弹窗约 150–220ms；
  这些是常见反馈的起点，不限制有依据的布局连续性、手势或内容展示动效。
  简单效果优先 CSS，复杂需求比较项目已有运行时。连续装饰动画须有明确产品收益、
  性能预算、暂停/降级策略；不作为“提升完成度”的默认动作。
- 避免让祖先和所有子控件同时过渡继承的文字颜色，造成主题切换时文字对比度滞后。
  按下效果不改变布局尺寸，减少动态效果设置应关闭非必要过渡。

## 按项目调整的边界

密集数据可减少容器内边距，而不是缩小点击目标；复杂任务可增加分组和渐进披露，
而不是删掉反馈。强调色与视觉素材可以承担导航、内容分组或产品表达，但须有可说明的用途，
不能仅以个人偏好打散现有设计系统。没有足够收益时保留现状，不用“更丰富”作为无限美化理由。
